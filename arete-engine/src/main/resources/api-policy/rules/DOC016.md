# DOC016 — Schema example omits a required field

## Intent

A schema `example` should be a complete instance. If it leaves out a
`required` property, the example is not something the API would actually
accept, and generated mocks and tests built from it will be wrong.

## Diagnostic

```yaml
Customer:
  type: object
  required: [id, name, email]
  properties:
    id: { type: string }
    name: { type: string }
    email: { type: string }
  example:
    id: "c-1"
    name: "Ada Lovelace"
```

## Compliant

```yaml
Customer:
  type: object
  required: [id, name, email]
  properties: { id: { type: string }, name: { type: string }, email: { type: string } }
  example:
    id: "c-1"
    name: "Ada Lovelace"
    email: "ada@example.com"
```

## Detection and scope

The rule has `schema` scope and uses the `example-validity` rule with
`check: covers-required`. For each component schema whose `example` is an
object, every name in the schema's `required` array must be a key in the
example; each missing name is reported.

## Configuration and limitations

Only object examples on component schemas are checked. Nested required
fields, parameter examples, and inline schemas are out of scope.
