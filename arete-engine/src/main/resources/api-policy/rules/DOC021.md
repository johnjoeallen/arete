# DOC021 — Operation summary has too few words

## Intent

A one- or two-word summary ("Get", "List users") rarely conveys what an
operation actually does. A meaningful summary is a short phrase, not a label.

## Detection and scope

The rule has `operation-summary` scope and uses the `text-style` rule:

```yaml
parameters: { minimum-words: 3 }
```

For every non-empty operation summary, the rule counts its **substantive
words** — whitespace-separated tokens with leading/trailing punctuation
stripped, keeping only those that contain a letter — and reports when there
are fewer than 3. The finding says `Operation summary has too few words to be
meaningful`. Missing or blank summaries are ignored; DOC001 covers those.

## Review-candidate example

```yaml
paths:
  /customers:
    get:
      summary: List
```

## Compliant example

```yaml
paths:
  /customers:
    get:
      summary: List all customer records
```

## Configuration and limitations

`minimum-words: 3` is fixed by DOC021. Word counting is mechanical: it does
not check that the words are informative, only that there are enough of them.
Punctuation-only and numeric-only tokens (`-`, `v2`) do not count. It does not
inspect the operation description.
