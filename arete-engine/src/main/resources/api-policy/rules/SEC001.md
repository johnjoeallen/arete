# SEC001 — Sensitive schema property is exposed by name

## Intent

Schema property names should make sensitive data explicit so it can receive
appropriate handling and review. Policies may override the pattern.

## Review-candidate example

```yaml
properties:
  password: { type: string, format: password }
```

## Compliant example

```yaml
properties:
  credential_reference: { type: string }
```

## Detection and scope

The rule has `property` scope and reports schema properties whose names match
the configured case-insensitive sensitive-data pattern.

## Configuration and limitations

`pattern` selects the sensitive names. The rule is name-based: it does not
inspect values, formats, examples, encryption, storage, or runtime handling.
