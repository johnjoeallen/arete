# DOC009 — Operation summary is not action-oriented

## Intent

Operation summaries should concisely describe what the operation does. An
action-oriented summary helps readers scan generated documentation and
understand the operation without inspecting its path or schema.

## Detection and scope

The rule has `operation-summary` scope and uses the `text-style` rule:

```yaml
parameters:
  match: non-action-oriented
  action-prefixes: [Get, List, Create, Update, Delete, Replace, Search, Find, Cancel, Activate, Deactivate]
```

The rule ignores missing or blank summaries for this rule. For every other
summary, a trimmed summary that **starts with one of the `action-prefixes`
above as a whole word** (case-sensitive) is treated as action-oriented and is
not reported — `List customers` and `List.` pass, `Listing customers` does not.
Other non-empty summaries are reported with `Operation summary is not
action-oriented`. A policy can supply its own `action-prefixes` (a YAML list,
or a comma-separated string).

## Review-candidate example

This summary is reported:

```yaml
paths:
  /customers:
    get:
      summary: Customer collection
      responses: { '200': { description: OK } }
```

`List customers` would satisfy the rule’s action-prefix heuristic.

## Compliant example

```yaml
paths:
  /customers:
    get:
      summary: List customers
      responses: { '200': { description: OK } }
```

## Parameters, references, and limitations

`match: non-action-oriented` selects the fixed prefix list. This rule does not
check summary presence, capitalization, punctuation, length, HTTP method, path,
or business meaning. The rule is case-sensitive and may report a useful
summary that uses another verb, while missing awkward wording beginning with a
recognised prefix. DOC001 handles missing summaries separately. Findings are
documentation review candidates.
