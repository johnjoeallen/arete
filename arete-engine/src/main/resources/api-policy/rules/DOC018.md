# DOC018 — Operation uses an undeclared tag

## Intent

Every tag an operation references should be defined in the top-level `tags`
list. Declaring tags in one place gives each a description and a stable order,
and catches typos that would otherwise split one group into two.

## Detection and scope

The rule has `api` scope and uses the `tag` matcher with `check: declared`.
It collects the distinct tag names used across all operations and reports each
one that has no matching entry in the top-level `tags` list.

## Review-candidate example

```yaml
tags:
  - name: orders
    description: Order operations.
paths:
  /orders:
    get:
      tags: [order]
      responses: { '200': { description: OK } }
```

`order` is reported — the declared tag is `orders`.

## Compliant example

```yaml
tags:
  - name: orders
    description: Order operations.
paths:
  /orders:
    get:
      tags: [orders]
      responses: { '200': { description: OK } }
```

## Limitations

The comparison is exact and case-sensitive. The rule does not check whether a
declared tag is unused.
