# DOC020 — API does not declare a license

## Intent

`info.license` states the terms under which the API description — and often
the API — may be used. Consumers, procurement, and automated catalogues rely
on it; an absent or URL-less license forces every consumer to ask. The
`license` object should carry both a `name` (an SPDX identifier such as
`Apache-2.0`, or a product name) and a `url` to the full text.

## Detection and scope

The rule has `api` scope and uses the `metadata` matcher with
`required: license`. It reports at `/info/license` when:

- there is no `info.license`, or its `name` is missing or blank, or
- the license has a name but no `url`.

One finding is emitted per document.

## Diagnostic

```yaml
info:
  title: Billing API
  version: 2.1.0
  # no license
```

## Compliant

```yaml
info:
  title: Billing API
  version: 2.1.0
  license:
    name: Apache-2.0
    url: https://www.apache.org/licenses/LICENSE-2.0
```

## Configuration and limitations

`required: license` is the mode used here. The rule does not check that the
`name` is a valid SPDX identifier or that the `url` resolves; it checks only
that both fields are present and non-blank. OpenAPI 3.1's `license.identifier`
is outside the current model.
