# DOC001 — Operation summary is missing

## Intent

Every operation should provide a concise summary describing its purpose.

## Detection and scope

The rule has `operation` scope and uses the `operation` rule:

```yaml
parameters: { summary: absent }
```

For each operation, the rule trims its summary. It reports when the value
is absent or blank, at the operation pointer, with `Operation summary is
missing`. A whitespace-only summary is therefore equivalent to no summary.

## Review-candidate example

```yaml
paths:
  /customers:
    get:
      responses: { '200': { description: Customer collection } }
```

Add a concise purpose, such as `List customers`.

## Compliant example

```yaml
paths:
  /customers:
    get:
      summary: List customers
      responses: { '200': { description: Customer collection } }
```

## Parameters, references, and limitations

`summary: absent` selects this check. The rule does not judge summary
quality, length, capitalization, grammar, descriptions, operation IDs, or
whether the summary reflects runtime behavior. Referenced operations count
only when the host resolves them into its normalised operation model. DOC002–
DOC009 cover separate style concerns; this rule only checks presence.
