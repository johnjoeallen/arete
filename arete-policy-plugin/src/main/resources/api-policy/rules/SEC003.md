# SEC003 — Sensitive data is embedded in a path parameter

## Intent

Sensitive identifiers or credentials should not be placed in a URL path,
where the complete URL is frequently logged and retained.

## Review-candidate example

```yaml
parameters:
  - name: access_token
    in: path
    required: true
    schema: { type: string }
```

## Compliant example

```yaml
parameters:
  - name: customer_id
    in: path
    required: true
    schema: { type: string }
```

## Detection and scope

The rule has `path-parameter` scope and reports path parameters whose names
match the configured sensitive-data pattern.

## Configuration and limitations

`pattern` selects the sensitive names. The rule is name-based and does not
inspect the value, server logs, or runtime URL handling.
