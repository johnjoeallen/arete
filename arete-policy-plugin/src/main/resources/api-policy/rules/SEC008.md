# SEC008 — Sensitive data is carried in a custom header

## Intent

Sensitive values in headers should be explicitly reviewed because headers are
often logged or forwarded by infrastructure.

## Review-candidate example

```yaml
parameters:
  - name: X-Api-Key
    in: header
    schema: { type: string }
```

## Compliant example

```yaml
parameters:
  - name: correlation-id
    in: header
    schema: { type: string }
```

## Detection and scope

The rule has `header` scope and reports header parameters whose names match the
configured sensitive-data pattern.

## Configuration and limitations

`pattern` selects the sensitive names. The rule does not distinguish a secure
secret-management scheme from an exposed credential based on the header name
alone.
