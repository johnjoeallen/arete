# DOC017 — Tag has no description

## Intent

Every tag declared in the top-level `tags` list should carry a `description`.
The description is what documentation tools show as the section blurb for the
operations under that tag; without it the grouping is a bare label.

## Detection and scope

The rule has `api` scope and uses the `tag` matcher with `check: documented`.
Each top-level `tags` entry whose `description` is missing or blank is
reported once at its tag pointer.

## Review-candidate example

```yaml
tags:
  - name: orders
paths: {}
```

`orders` is reported.

## Compliant example

```yaml
tags:
  - name: orders
    description: Create, retrieve, and cancel customer orders.
paths: {}
```

## Limitations

The rule only inspects entries in the top-level `tags` list. A tag used by an
operation but never declared there is out of scope for this rule — see
DOC018.
