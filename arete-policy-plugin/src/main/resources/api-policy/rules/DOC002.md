# DOC002 — Operation summary does not begin with a capital letter

## Intent

Operation summaries should begin with a capital letter for consistent presentation.

## Detection and scope

The rule has `operation-summary` scope and uses the `text-style` rule:

```yaml
parameters: { initial-capital: false }
```

The current rule ignores missing or blank summaries and reports summaries
whose first character is lowercase (the configured `false` condition). The
finding says `Operation summary does not begin with a capital letter` and
points to the operation. Leading whitespace is trimmed before the first
character is checked.

## Review-candidate example

```yaml
paths:
  /customers:
    get:
      summary: list customers
      responses: { '200': { description: OK } }
```

## Compliant example

```yaml
paths:
  /customers:
    get:
      summary: List customers
      responses: { '200': { description: OK } }
```

## Parameters, references, and limitations

`initial-capital: false` is the rule’s current rule contract, despite the
rule’s prose describing the preferred capitalised style. The rule checks
only the first Unicode character’s uppercase property; it does not inspect
grammar, punctuation, methods, descriptions, or runtime behavior. DOC001
covers missing summaries. Findings are presentation-style candidates.
