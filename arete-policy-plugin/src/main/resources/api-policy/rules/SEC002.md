# SEC002 — Sensitive data is accepted in a query parameter

## Intent

Sensitive values should not be placed in query strings, which are commonly
captured by logs, browser history, caches, and intermediary systems.

## Review-candidate example

```yaml
parameters:
  - name: password
    in: query
    schema: { type: string }
```

## Compliant example

```yaml
parameters:
  - { name: credential_reference, in: query, schema: { type: string } }
```

## Detection and scope

The rule has `query-parameter` scope and reports query parameters whose names
match the configured sensitive-data pattern.

## Configuration and limitations

`pattern` selects the sensitive names. The rule does not inspect parameter
values or determine whether a particular transport, proxy, or logging policy
is safe.
