---
id: SEC005
category: Sensitive data
matcher: sensitive-search
scope: operation
parameters:
  search-pattern: "(^|[-_])(q|query|search|term|text)([-_]|$)"
  sensitive-pattern: "password|secret|token|api[_-]?key|ssn|credit[_-]?card"
---

# SEC005 — Operation permits searching sensitive fields

## Intent

An operation should not expose both a free-text search input and a query field
for sensitive data unless that behavior has been explicitly reviewed.

## Review-candidate example

```yaml
parameters:
  - { name: search, in: query, schema: { type: string } }
  - { name: ssn, in: query, schema: { type: string } }
```

## Compliant example

```yaml
parameters:
  - { name: search, in: query, schema: { type: string } }
  - { name: customer_reference, in: query, schema: { type: string } }
```

## Detection and scope

The rule has `operation` scope and reports when one operation has both a
search-like query parameter and a query parameter whose name matches the
sensitive-data pattern.

## Configuration and limitations

`search-pattern` and `sensitive-pattern` define the two name sets. The rule
does not inspect request bodies, values, database fields, or actual search
implementation.
