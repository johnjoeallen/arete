# DOC015 — Operation description is missing

Every operation should carry a `description` in addition to a `summary`. The
summary is the one-line label; the description is where behaviour, side
effects, and edge cases are explained.

## Diagnostic

```yaml
/customers:
  post:
    summary: Create a customer
    responses: { '201': { description: Created } }
```

## Compliant

```yaml
/customers:
  post:
    summary: Create a customer
    description: >
      Registers a new customer. The email address must be unique; a duplicate
      returns 409.
    responses: { '201': { description: Created } }
```

## Detection and scope

The rule has `operation` scope and uses the `operation` rule with
`description: absent`. An operation whose `description` is missing or blank is
reported. DOC001 covers the `summary`.

## Configuration and limitations

The rule checks presence, not length or quality.
