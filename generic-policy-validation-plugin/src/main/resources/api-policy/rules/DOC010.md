# DOC010 — operationId is missing or duplicated

Every operation should carry an `operationId`, and each `operationId` must be
unique across the document. Generators use it to name client methods; a
missing or repeated value produces broken or colliding code.

## Diagnostic

```yaml
/customers:
  get: { operationId: list, responses: { '200': { description: OK } } }
/orders:
  get: { operationId: list, responses: { '200': { description: OK } } }
```

## Compliant

```yaml
/customers:
  get: { operationId: listCustomers, responses: { '200': { description: OK } } }
/orders:
  get: { operationId: listOrders, responses: { '200': { description: OK } } }
```

## Detection and scope

The rule has `operation` scope and uses the `operation-metadata` rule with
`check: unique-operation-id`. An operation with no `operationId` is reported;
the second and later operations sharing an `operationId` are reported against
the first.

## Configuration and limitations

Comparison is exact and case-sensitive. The rule does not check that the
`operationId` follows a naming convention.
