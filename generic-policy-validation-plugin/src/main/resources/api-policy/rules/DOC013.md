# DOC013 — Schema property lacks a description or example

Every schema property should carry a `description` and an `example` so that
generated documentation and mock servers are useful.

## Violation

```yaml
components:
  schemas:
    Customer:
      properties:
        displayName: { type: string }
```

## Compliant

```yaml
components:
  schemas:
    Customer:
      properties:
        displayName:
          type: string
          description: The customer's preferred display name.
          example: Ada Lovelace
```

## Detection and scope

The rule has `property` scope and uses the `documentation-completeness`
detector with `require: both`. Each component-schema property is checked; one
occurrence is reported per property missing a description, an example, or
both.

## Configuration and limitations

`require` may be narrowed to `description` or `example`. The detector checks
presence, not quality, and inspects component schemas only.
