# DOC007 — API identifier is missing

An API should declare its configured `x-api-id` extension so it can be
unambiguously identified by API-management tooling.

## Intent and detection

The identifier extension gives catalogues and API-management systems a stable
identity independent of a display title or server URL. The rule has `api`
scope and uses the `metadata` detector with `required: identifier`. It reads
the top-level `x-api-id` extension and reports one finding at `/` when its
value is absent, blank, or not a string. Any non-blank string satisfies the
check.

## Examples

Review candidate:

```yaml
openapi: 3.0.3
info: { title: Customer API, version: 1.0.0 }
```

Compliant example:

```yaml
x-api-id: customer-api
```

The extension identifies the API; it does not validate ownership or access.

## Configuration and limitations

`required: identifier` is fixed by DOC007. The detector does not validate a
format, uniqueness, URI syntax, or registry membership, and it does not infer
an identifier from `info.title`, operation IDs, or server URLs. Only the
normalised top-level extension is inspected; missing information is reported
as a documentation candidate.
