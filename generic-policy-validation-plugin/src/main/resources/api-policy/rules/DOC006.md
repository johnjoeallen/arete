# DOC006 — API metadata is incomplete

An API description should provide a title, description, contact name and email,
and a semantic document version so consumers can identify and support it.

## Intent and detection

Complete metadata gives consumers enough context to identify an API, contact
its owner, and understand the compatibility version of the document. The rule
has `api` scope and uses the `metadata` detector with `required: complete`.
It checks that `info.title`, `info.description`, contact name, and contact
email are non-blank strings, and that `info.version` is a semantic version.
Missing fields produce findings at `/info`; multiple missing fields produce
one finding per field.

The accepted version shape is a numeric major, minor, and patch (`1.2.3`),
with optional prerelease and build suffixes. The detector checks the document’s
`info.version`, not the OpenAPI specification version.

## Review-candidate example

This metadata is incomplete because description, contact, and a semantic
document version are absent:

```yaml
info:
  title: Customer API
  version: draft
```

## Compliant example

```yaml
info:
  title: Customer API
  description: Manage customers.
  version: 1.2.3
  contact:
    name: API Team
    email: api@example.test
```

## Configuration and limitations

`required: complete` selects all five checks. The detector does not verify
email deliverability, contact identity, version ordering, or the truth of the
description. Blank or non-string values are missing, and absent contact
objects cannot supply contact fields. References and runtime registry data are
not consulted; findings are documentation candidates.
