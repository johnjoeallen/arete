# DOC003 — Operation summary is not sentence case

## Intent

Operation summaries should use consistent sentence case so generated API
documentation is easy to scan and does not mix title-like and sentence-like
presentation.

## Detection and scope

The rule has `operation-summary` scope and uses the `text-style` detector:

```yaml
parameters: { convention: sentence-case }
```

Blank or missing summaries are ignored. The detector applies its sentence-case
heuristic to every other summary and reports a match with `Operation summary
is not sentence case`. The check is based on the summary text only; it does
not inspect the operation method, path, or description.

## Review-candidate example

```yaml
paths:
  /customers:
    get:
      summary: list customers
      responses: { '200': { description: OK } }
```

Use a consistent sentence-style form such as `List customers` according to
the project’s chosen writing convention.

## Compliant example

```yaml
paths:
  /customers:
    get:
      summary: List customers
      responses: { '200': { description: OK } }
```

## Parameters, references, and limitations

`convention: sentence-case` selects this heuristic. It does not validate
grammar, punctuation, acronyms, capitalization after the first word, or
business meaning, and its handling of all-capital text follows the detector’s
regular-expression heuristic. Missing summaries are owned by DOC001.
Referenced operations count only after host normalisation; findings are style
review candidates.
