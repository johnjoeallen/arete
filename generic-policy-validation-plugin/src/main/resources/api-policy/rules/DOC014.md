# DOC014 — Parameter lacks a description or example

Every parameter should carry a `description` and an `example` so a caller
knows what to send without reading the implementation.

## Diagnostic

```yaml
parameters:
  - name: status
    in: query
    schema: { type: string }
```

## Compliant

```yaml
parameters:
  - name: status
    in: query
    description: Filter by lifecycle status.
    example: active
    schema: { type: string }
```

## Detection and scope

The rule has `parameter` scope and uses the `documentation-completeness`
rule with `require: both`. Path-level and operation-level parameters are
checked; an example declared on the parameter or on its schema counts.

## Configuration and limitations

`require` may be narrowed to `description` or `example`. The rule checks
presence, not quality.
