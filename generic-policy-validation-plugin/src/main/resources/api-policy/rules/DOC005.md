# DOC005 — Operation summary is excessively long

The operation summary should remain concise. Longer explanations belong in the operation description.

## Detection and scope

The rule has `operation-summary` scope and uses the `text-style` detector:

```yaml
parameters: { maximum-length: 120 }
```

For every non-empty operation summary, the detector reports when its character
length is greater than 120. The finding says `Operation summary exceeds the
configured maximum length`. Missing or blank summaries are ignored by this
rule; DOC001 checks missing summaries separately.

## Review-candidate example

```yaml
paths:
  /customers:
    get:
      summary: This is an unnecessarily long operation summary that should be shortened and moved into the operation description when it contains extensive explanation, caveats, examples, or workflow guidance for readers.
```

## Compliant example

```yaml
paths:
  /customers:
    get:
      summary: List customers
```

## Configuration and limitations

`maximum-length: 120` is fixed by DOC005. The detector counts the summary
string’s characters, does not inspect the description or words, and does not
infer whether a long summary is useful. Whitespace is trimmed before checking;
referenced operations count only after host normalisation. Findings are style
review candidates.
