# DOC011 — Operation is not tagged

## Intent

Every operation should be assigned at least one tag. Tags drive grouping in
generated documentation and SDKs; an untagged operation is filed under a
default bucket and is easy to miss.

## Diagnostic

```yaml
/customers:
  get:
    summary: List customers
    responses: { '200': { description: OK } }
```

## Compliant

```yaml
/customers:
  get:
    tags: [Customers]
    summary: List customers
    responses: { '200': { description: OK } }
```

## Detection and scope

The rule has `operation` scope and uses the `operation-metadata` rule with
`check: tags-present`. An operation whose `tags` list is empty or absent is
reported once.

## Configuration and limitations

The rule checks that at least one tag is present, not that the tag is
declared in the top-level `tags` array or that it is meaningful.
