# SEC009 — Server URL exposes an internal host

## Intent

A published `servers` entry should point at a routable, external host. A
`localhost`, private-range, single-label, or `.internal`-style URL leaks
infrastructure detail and produces a spec clients cannot call.

## Diagnostic

```yaml
servers:
  - url: https://payments.svc.internal/v1
  - url: http://localhost:8080
```

## Compliant

```yaml
servers:
  - url: https://api.example.com/v1
```

## Detection and scope

The rule has `api` scope and uses the `server-url` rule with
`check: internal-host`. Each `servers[].url` is parsed for its host; a host
that is `localhost`, a loopback or RFC 1918 address, a bare single-label name,
or ends in `.internal` / `.local` / `.corp` / `.intranet` / `.lan` is
reported.

## Configuration and limitations

The rule uses host-shape heuristics, not DNS or routing data. A public
hostname that happens to resolve internally is not detected.
