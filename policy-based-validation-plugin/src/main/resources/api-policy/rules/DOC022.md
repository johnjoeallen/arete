# DOC022 — Operation summary contains an unusually long word

## Intent

A single very long "word" in a summary is almost always a run-on identifier,
a pasted URL, or a missing space — not prose. Flagging it catches summaries
that were never really written for a reader.

## Detection and scope

The rule has `operation-summary` scope and uses the `text-style` rule:

```yaml
parameters: { maximum-word-length: 30 }
```

For every non-empty operation summary, the rule checks each **substantive
word** (whitespace-separated, edge punctuation stripped, must contain a
letter) and reports when any one of them is longer than 30 characters. The
finding says `Operation summary contains an unusually long word`. Missing or
blank summaries are ignored; DOC001 covers those.

## Review-candidate example

```yaml
paths:
  /customers:
    get:
      summary: ReturnsTheFullyExpandedCustomerAggregateWithNestedOrders
```

## Compliant example

```yaml
paths:
  /customers:
    get:
      summary: Returns the fully expanded customer aggregate
```

## Configuration and limitations

`maximum-word-length: 30` is fixed by DOC022. The check is per word, not for
the whole summary — DOC005 owns the overall-length check. It compares
character counts only and does not judge whether a long token is a legitimate
domain term.
