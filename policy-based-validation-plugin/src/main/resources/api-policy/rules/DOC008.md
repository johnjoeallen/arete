# DOC008 — API audience is missing

An API should declare its intended `x-audience` so consumers and governance
tooling can apply the appropriate publication and hostname policies.

## Intent

The audience extension identifies whether an API is intended for internal,
partner, or public consumers. The rule has `api` scope and uses the `metadata`
rule with `required: audience`. It reads the top-level `x-audience`
extension and reports one API-level finding at `/` when its value is absent,
blank, or not a string. A non-blank string satisfies the check.

## Detection and scope

The rule has `api` scope and reports a missing, blank, or non-string top-level
`x-audience` value at `/`.

## Review-candidate example

Review candidate:

```yaml
openapi: 3.0.3
info: { title: Customer API, version: 1.0.0 }
x-audience: internal
```

## Compliant example

```yaml
x-audience: public
```

The extension is metadata, not a security control; it does not grant or
restrict access.

## Configuration and limitations

`required: audience` is fixed by DOC008. The rule does not validate an
allowed vocabulary, inspect descriptions, infer audience from servers or
security requirements, or check runtime deployment. Referenced or
vendor-specific metadata is considered only when the host exposes it as the
top-level extension. Missing information produces a documentation candidate.
