# DOC019 — Tag is declared more than once

## Intent

Each entry in the top-level `tags` list should have a distinct `name`. A
duplicate name means two descriptions, two possible orderings, and undefined
behaviour in documentation tools — some show the first, some the last, some
merge. It is usually the result of adding a tag without noticing it already
exists.

## Detection and scope

The rule has `api` scope and uses the `tag` matcher with `check: unique`.
Entries in `tags` are grouped by `name`; for any name declared more than once
the first entry is left alone and each later one is reported at its pointer.

## Diagnostic

```yaml
tags:
  - name: orders
    description: Create and retrieve orders.
  - name: orders
    description: Order lifecycle operations.
```

The second `orders` entry is reported.

## Compliant

```yaml
tags:
  - name: orders
    description: Create, retrieve, and cancel orders.
```

## Configuration and limitations

`check: unique` is the rule's only mode. The comparison is exact and
case-sensitive; `Orders` and `orders` are treated as different tags (see
`CASE008` for tag-name casing). The rule does not compare the duplicates'
descriptions.
