# SEC006 — Identifier property is not a string

## Intent

Resource identifiers should use strings to avoid client-side numeric overflow
and preserve compatibility if the identifier generation strategy changes.

## Review-candidate example

```yaml
properties:
  customer_id: { type: integer }
```

## Compliant example

```yaml
properties:
  customer_id: { type: string }
```

## Detection and scope

The rule has `property` scope and reports identifier-like property names whose
schema type is not `string`.

## Configuration and limitations

`check: string` selects the type check and `name-pattern` selects identifier-
like names. The rule does not validate the identifier format or uniqueness.
